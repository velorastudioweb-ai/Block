# Final Project Audit — Verity

**Date:** 2026-11-20
**Auditor:** Senior Full-Stack / Blockchain Security / QA
**Project:** Verity — Blockchain-Based Academic Certificate Issuance and Verification System Using Proof of Authority (PoA)

## 1. Source Code Audit

### Frontend (`apps/web/main.jsx`, `style.css`)
- Single-page React app with role-based views (university, student, super admin).
- White/dark-green Verity branding preserved.
- Responsive media queries present for tablet/mobile.
- API client handles FormData and JSON; errors surfaced via alerts.
- No console errors observed during build.
- **Issue found & fixed:** QR image endpoint originally required auth (img tag can't send Bearer token). Changed to public endpoint. Fixed.
- **Issue found & fixed:** Student PDF download was blocked by university-only ownership check. Extended to student/admin roles. Fixed.

### Backend (`apps/api/server.js`)
- Express + Zod validation + rate limiting.
- Auth via bcrypt + in-memory sessions.
- RBAC middleware (`requireRole`).
- Endpoints: login/logout/me, network, blocks, certificates (CRUD + pdf + qr), verify, verify-pdf, students, admin/*, integrity, events, register-university.
- **Issue found & fixed:** `users` array was cached at startup, so newly created student accounts couldn't log in. Changed to `readUsers()` on demand. Fixed.
- **Issue found & fixed:** University registration mutated in-memory config but config is loaded once; mutation works because same object reference. OK.

### Database
- JSON files (users, students, certificates, verification-logs, config, validator chains). No Prisma/SQLite (documented limitation).
- Foreign-key relationships enforced in application logic (universityId scoping).
- Unique constraints enforced in application logic (studentId per university, duplicate cert IDs in consensus).

### Blockchain Core (`packages/core/index.js`)
- SHA-256 via node:crypto. Deterministic canonical JSON (sorted keys).
- Ed25519 signatures via node:crypto.
- `validateCandidate`, `validateFinalized`, `validateChain` implemented.
- Previous-hash linking, height, proposer schedule, commitment, quorum all enforced.

### Consensus Engine (`apps/validator/server.js`)
- Three independent HTTP processes on ports 4101/4102/4103.
- Each has its own key file, chain file, vote-lock file.
- Endpoints: /status, /chain, /propose, /vote, /finalize, /sync.
- **Added:** /sync endpoint for catch-up after restart. Fixed gap.

### Certificate Generation (`apps/api/pdf.js`)
- PDFKit landscape certificate with university name, student, course, details, cert ID, QR code.
- QR encodes verification URL with cert ID.

### Authentication / Authorization
- bcrypt password hashing (cost 10).
- Random 32-byte session tokens, 8-hour expiry, in-memory.
- RBAC on all protected endpoints.
- Rate limiting 120 req/min on /api.

### Security
- Private keys in `data/` (gitignored), never sent to frontend.
- No SQL (JSON files) → no SQL injection. Zod validation on all inputs.
- Rate limiting present.
- **Limitation:** No TLS, in-memory sessions, no audit log table (documented).

### Environment Configuration
- `.env` not used; config in `data/config.json` (generated by setup).
- `DEMO_PASSWORD`, `PUBLIC_WEB_URL` env vars supported.
- Docker Compose provided (uses node images, runs npm install at startup).

## 4. Certificate Issuance Test

Executed via integration test + manual:
- Login → issue → verify → revoke. All steps confirmed.
- Invalid inputs rejected by Zod.
- Duplicate certificate IDs prevented by consensus (`Duplicate certificate`).
- Only approved universities can issue (checked in endpoint).
- Certificates marked finalized only after 2+ validator acks.

## 5. Certificate Verification Test

- By ID: `GET /api/verify/:id` → recomputes hash, checks signature, checks revocation.
- By PDF upload: `POST /api/verify-pdf` → SHA-256 of uploaded bytes vs finalized `documentHash`. Tampered PDF rejected.
- By QR: QR encodes `?id=...` → frontend opens verify page with pre-filled ID.

## 6. Revocation Test

- Only issuing university can revoke (endpoint checks `universityId === req.user.universityId`).
- Signed REVOKE transaction, validated by consensus.
- Original issuance preserved (append-only).
- Verification returns "Revoked" only after finalization.
- Previously downloaded PDFs: PDF hash still matches document commitment, but verification status is "Revoked" (metadata check returns revoked).

## 7. Database & Auth Audit

- Schema: defined in application logic.
- University-level isolation: all certificate/student queries filter by `universityId`.

- Input validation: Zod on all mutations.
- SQL injection: N/A (no SQL).
